## 4. Giải thích phần kỹ thuật đã thực hiện

### Vấn đề cần giải quyết

Phần này mô phỏng sự cố dữ liệu trong production để chứng minh ba điều. Thứ nhất, dữ liệu hỏng làm RAG trả lời sai mà không báo lỗi (silent failure). Thứ hai, lớp observability phát hiện được từng loại lỗi. Thứ ba, pipeline tự phục hồi về đúng trạng thái sạch. Ngoài ra còn cần ghép các module thành hai luồng chạy lặp lại được.

### Cách triển khai

**`corrupt_clean_dataframe`** làm việc trên bản sao và dùng `random.Random(42)`, nên mỗi lần chạy cho cùng một kết quả. Sáu kịch bản:
1. Bỏ 20% bài mới nhất.
2. Xoá trắng summary.
3. Chèn token rác vào summary.
4. Cắt title còn 7 ký tự.
5. Lùi `published` 365 ngày và cộng thêm 365 vào `age_days`.
6. Nhân đôi dòng.

Kịch bản 2–5 được chia cho các dòng khác nhau (`_RowPicker`) để tác động phân tán. Cuối cùng, `text_for_embedding` được dựng lại để lỗi đi vào cả vector.

**`phase1.main`** chạy theo thứ tự: ingest → clean → gate + freshness → index → test set cố định → evaluate → demo agent → report. Gate đặt trước index, fail thì `SystemExit(1)`.

**`corruption_flow.main`** gồm các bước:
1. Tiêm lỗi.
2. Chạy gate trên dữ liệu hỏng.
3. Cố tình index dữ liệu hỏng để đo tác động.
4. Nếu gate fail thì tự động gọi `repair_from_raw`: parse lại raw, áp đúng quy tắc cleaning và chạy hai lần để so fingerprint.
5. Chạy gate lại, chỉ index khi đạt.
6. Viết báo cáo 3 trạng thái.

### Input, output và contract

| Thành phần | Mô tả |
| --- | --- |
| Input | Clean dataframe 16 cột (`paper_id`, `title`, `summary`, `published`, `age_days`, `text_for_embedding`, …); `Settings.paths` |
| Output | Corrupted dataframe + log JSON; metrics JSON cho 3 trạng thái (thêm `state`, `collection`, `llm`, `judge_mode`, `by_question_type`); `repair_log.json`; 2 báo cáo Markdown |
| Module phụ thuộc | `ingestion.cleaning` (`refresh_derived_columns`, `build_clean_dataframe`, `dataset_fingerprint`), `observability.quality`, `evaluation.metrics`, `retrieval.index` |
| Module sử dụng output | `observability.reporting.generate_corruption_report`, bài demo CP6 |
| Điều kiện lỗi cần xử lý | Thiếu artifact pha 1 → thoát kèm hướng dẫn chạy `run_phase1.py`; gate pha 1 fail → không index; dữ liệu repair không đạt gate → không publish index; demo agent lỗi hoặc hết quota → ghi lỗi (đã che key) thay vì dừng pipeline |

python script/run_phase1.py
